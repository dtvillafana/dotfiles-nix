# Rogdesktop: 9 decode token/s context tuning

Requested 2026-11-08. This is an explicitly requested synthetic throughput/context
diagnostic, not an agent-quality benchmark. The original Q4/Qwen passes are
complete and independently audited, including the subsequently requested IQ2_M
48K experiment. No tuned profiles have been activated.

**Goal update:** the user lowered the minimum from **15 to 9 token/s** after the
initial split passes. Completed measurements are reused and reclassified against
9; their original recorded 15-token/s pass/fail fields are not rewritten.

## Scope and acceptance contract

- Host: rogdesktop, GTX 1070 8 GiB, Ryzen 5 2600X, 39 GiB RAM.
- Candidates: the installed Qwen3.8 27B abliterated Q4_K_M and K2 Horizon MoVA
  36B-A4B abliterated imatrix Q4_K_M. These are the two quality-oriented candidates
  selected from the current inventory, not a proven ranking of the edited GGUFs.
  The Qwen model's published reasoning/coding results and IFM's MoVA comparison
  motivate the selection; base-model benchmarks do not validate abliteration.
- Keep the immutable weight revisions/hashes and the deployed CUDA 12 llama.cpp
  0.8.0 parser-fix runtime fixed. No new weight quantizations, speculative model,
  hardware change, desktop-application shutdown, or artificial extra GPU work.
- One temporary worker at a time. The public inference socket/router is stopped
  during the pass, with permission already granted to interrupt local inference.
- Reserve **1,536 MiB free VRAM**; monitor actual free memory once per second.
  Stop only the temporary worker if it crosses the reserve or starts swapping.
  Workers run in disposable systemd units with `MemorySwapMax=0`, matching the
  production no-swap policy, and cgroup memory/swap usage is recorded.
  Automatic whole-layer fitting targets 1,792 MiB to leave additional margin.
- Six batch threads and 64-token microbatches. Short screens compare generation
  threads 4/6/8, whole-layer versus mixed placement, flash attention, and mapped
  versus resident weights. MoVA keeps routed FFN experts on CPU and compares
  8/12/16/20/24 attention value-expert blocks on CPU. Existing cache precision is
  retained: f16 for Qwen, Q4 for MoVA.
- First screen at **1,024 allocated context**, 256 uncached input tokens and
  128 generated tokens, twice. This small context is diagnostic only, not a
  proposed OpenCode/Hermes configuration.
- Validate promising operating points with **512 generated tokens twice** after
  filling **context minus 768 tokens**. Require both raw decode rates to be
  **at least 9.0 token/s**, exact uncached input counts, no truncation, no swap,
  and the VRAM reserve. Warm-up/loading is excluded; prefill and wall time are
  reported separately. Forced-length `ignore_eos` is used only for this synthetic
  diagnostic, not to claim natural agent completion.
- Exponentially bracket the first failing context, then refine at 256-token KV
  padding granularity. Revalidate the final passing and adjacent failing points.
  A failed short-context floor produces **no qualifying maximum**, not a made-up
  passing context or a substitution of a weaker model.
- Leave persistent settings/default models unchanged during tuning. Both earlier
  GLM definitions were subsequently removed from configuration at the user's
  request; their cached weights and validation artifacts are retained.

### Lossless speculative-decoding follow-up

The next explicit request asks for a previously untested supported optimization
on the unchanged selected models. `speculative-009-15tps/` tests **n-gram simple**
and **n-gram map-k** drafting on both MoVA Q4 and Qwen Q4, plus Qwen's embedded
MTP head as a CPU draft if the installed runtime/model combination supports it.
No draft-model download or weight-quantization change is used. Supported flags
are verified against the actual binary's `--help`; failures remain in the ledger.

This experiment uses a distinct protocol, kept outside the legacy `pass-*`
ledger glob: **2,048 context**, two frozen, non-repeated natural coding/reasoning
prompts, and 512 generated tokens per prompt. Each variant uses exactly the same
tokenized input and greedy sampling as a fresh non-speculative control with the
same placement. All **512 output token IDs and text** must match that control
for both prompts. A mismatch is an unverified exact-output result, not an
assumption that the algorithm is lossy; floating-point batch effects can matter.

Synthetic acceptance flags (`--spec-synth-*`), repeated filler, and token-copy
tasks are prohibited. The effective decode rate is the minimum of the runtime
rate and a conservative **511 / wall-time-after-measured-prefill** rate, so
unaccounted draft/verification work cannot manufacture a passing result. Both
rates must reach **15 token/s** before starting a context search. Passing two
prompts would demonstrate only workload-specific throughput/output equivalence,
not a universal speed or losslessness guarantee. The same VRAM/no-swap guards
and sequential quiet-window policy remain in force. The runner restores public
socket activation on exit. `audit_speculative15.py` independently verifies
outputs, request equivalence, timings, and telemetry.

The first speculation pass completed with **six safe paired trials** audited:

| MoVA control | 9.670 / 9.913 token/s | Reference |

| MoVA n-gram map-k | **15.931 / 12.947 token/s** | No / No |
