## Nix / NixOS: verify before editing

- For every Nix-related task, use the `nixos` MCP server (`mcp-nixos`) before recommending or changing package attributes, modules, options, or Nix library functions. Discover its tools if they are not already visible; do not guess names from memory and wait for evaluation to catch mistakes.
- Use its `nix` tool to search, then request details for the exact package attribute or option. Choose the correct source (`nixos`, `home-manager`, `darwin`, `nixvim`, or `noogle`) and check option types, defaults, examples, and required imports. Do not confuse NixOS and Home Manager options.
- Inspect the project's `flake.nix`, `flake.lock`, existing modules, and instructions first. Query available channels and select the matching release for NixOS lookups; do not silently treat unstable or a moving stable alias as the project's pinned version.
- Online search results are discovery aids, not proof that an option or package exists in the pinned inputs. Use `nix(action="flake-inputs", type="list")` and its `ls`/`read` operations from the project's directory to inspect the actual input sources, especially for release differences, third-party modules, and flake-parts options. If the MCP process is not running in that project, resolve the locked input store paths with local Nix commands and read those sources directly instead. Verify the module export and explicit import/activation path, not just the option name.
- If the MCP server is unavailable or a lookup fails, say so. Fall back to inspecting the pinned local source or official documentation, clearly identify what remains unverified, and never present a guessed attribute as confirmed. Do not install an unpinned replacement server.
- Prefer declarative Nix expressions and existing module options over imperative scripts. Keep expressions simple; factor out bindings only when they improve clarity or avoid repetition.
- Pin external inputs through the flake lock file. Do not use impure fetches.
- Use `nix fmt` for Nix formatting. If `nix fmt` is unavailable use `nixfmt`.
- MCP lookups do not replace evaluation or builds. After source verification and formatting, ask the user to evaluate the affected flake/configuration when practical; distinguish lookup/source checks from checks actually run, and never claim a successful evaluation or build without evidence.
- If something needs multiple dependencies, first try to get them all in a Nix shell environment. If this is not a one-off or requires NixOS configuration changes, recommend updating the NixOS configuration to support it, then attempt a different method.
